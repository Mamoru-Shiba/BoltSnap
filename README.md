# BoltSnap

Windows のタスクバーの上に重ねて表示する、常駐の「時間と草」バー。

- 今日の 0〜24 時のタイムライン（PC を操作していた時間・現在時刻）
- 第何週・何日目・年末までの残り日数
- 1 日 1 マスの年間の草（稼働が長いほど濃く、未来の日は枠のみ）

キーボード・マウスの操作の有無（1 分単位）だけを記録します。入力内容・アプリ名・ウィンドウ名は取得せず、外部通信もしません。

## 仕組み

- 帯はタスクバーに重ねて表示します。画面領域は確保しないので、他のウィンドウの大きさは変わりません。
- 最後のアイコンの右から、天気ウィジェットまたは通知領域（時計・トレイ）の手前までの空きを測り、そこに横いっぱいに広げます。時間帯バーと草はその幅に合わせて広がります。
- 空きは UI Automation でタスクバーのボタンの位置を読んで測り、アイコンの増減に合わせて 16 秒ごとに測り直します（アイコンが増えてから最大 16 秒ほど、帯が重なることがあります）。読めないときは、通知領域の左に固定幅で置きます。
- タスクバーが前面に出ても隠れないよう、2 秒ごとに位置と前後関係を保ちます。全画面のアプリやプレゼン中は自動で隠れます。
- アイコンが多く空きが最小幅（300px 相当）より狭いときは、最小幅で右に寄せるため、左のアイコンに少し重なります。

## 使い方

- 草にカーソルを重ねる: 左のテキストが、その日の日付と稼働時間に切り替わります。
- 右クリック（帯またはトレイアイコン）: 「ログイン時に自動起動」の切替と「終了」

## 開発

.NET 8 SDK が必要です。

```bash
dotnet build
dotnet test
```

Windows 用の実行ファイルの作成（Windows 上で実行）:

```powershell
# Native AOT（推奨。単一の exe、約 1.6MB）。Visual Studio の「C++ によるデスクトップ開発」が必要
dotnet publish src/BoltSnap -c Release -r win-x64 -p:PublishAot=true -o publish

# 通常ビルド（.NET ランタイム同梱）。WSL/Linux からも作れる
dotnet publish src/BoltSnap -c Release -r win-x64 --self-contained -p:PublishTrimmed=true -o publish
```

## 構成

```
src/
├── BoltSnap.Core/   純粋ロジックと保存（OS 非依存）
│   ├── Engines/     カレンダー・稼働判定・草の配置・帯のレイアウト
│   └── Services/    稼働の記録と保存
└── BoltSnap/        Win32 の UI（AppBar・GDI 描画・トレイ）
tests/
└── BoltSnap.Tests/  xUnit（Core を対象）
```

## メモリの目安（実測）

| ビルド | プライベート | ワーキングセット | 配布物 |
|--------|-------------|-----------------|--------|
| Native AOT | 約 4.2MB | 約 2.5MB（起動直後は約 4.5MB） | exe 1 つ（約 1.6MB） |
| 通常（ランタイム同梱） | 約 5.7MB | 約 21.5MB | 約 18MB |

- ワーキングセットには、Windows の共有 DLL（user32・gdi32 など）のページが含まれます。1 分ごとに使っていないページを OS に返しているため、Native AOT 版では小さくなります。
- タスクバーの空きの測定（UI Automation）は、常駐する本体ではなく、16 秒ごとに短時間だけ動く別プロセス（自分自身を `--probe` で起動）に任せています。UI Automation の DLL を本体に読み込まないので、本体のメモリは増えません。
- CPU は 30 秒でほぼ 0ms です。
